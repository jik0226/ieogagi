# 이어가기 보안 설계 — 설계 단계에서 보안약점을 막은 방법

> **용도**: 개발기획서 업데이트본의 "보안약점을 줄이기 위한 구조적 설계·구현 방법" 원고이자, 결선 발표·인터뷰와 서비스 개요서의 보안 항목 재료. 문서 속 커밋 번호는 비공개 개발 저장소 기준이다.
> **규칙**: 새 기법을 넣거나 바꾸면 이 문서에 같은 커밋으로 적는다. 49항목 대조는 [보안점검/49항목_체크리스트.md](보안점검/49항목_체크리스트.md), API는 [API_설계.md](API_설계.md).
> 최종 갱신 2026-10-18 (2·3차 외부 점검 조치 반영).

## 1. 한 줄 요약

**"약점이 생길 자리를 코드 구조에서 없앤다."** 인가·예외·로깅·입력 검증·비밀값을 각각 **한 곳**에 모으고, 그 한 곳을 거치지 않는 코드는 **자동 규칙(Semgrep·ruff·ESLint)과 테스트가 빌드를 막게** 했다. 개발자가 매번 조심해야 하는 구조가 아니라, 빠뜨리면 기계가 잡는 구조다.

### 공유 상수 불변화 (2026-10-13)

기획서 사실 대조에서 요청 처리에 쓰는 모듈 상수 일부가 가변 dict·set인 것을 찾았다(49항목 46번 Public 메서드로부터 반환된 Private 배열). 인가에 쓰는 초대·비활성화 권한표(`INVITABLE_ROLES`·`DISABLEABLE_ROLES`)는 읽기 전용 매핑(`MappingProxyType`) + `frozenset`으로, 보안 헤더(`SECURITY_HEADERS`)·오류 매핑(`STATUS_TO_ERROR`)·민감어 목록(`SENSITIVE_TERMS`)은 읽기 전용 매핑으로 바꿨다. 실행 중 어떤 코드도 권한표를 넓히거나 보안 헤더를 지울 수 없다. 남은 가변 상수는 마이그레이션 이름 규칙(`NAMING_CONVENTION`, 클래스 정의 때 한 번 읽음)과 운영 명령의 시드 데이터뿐이다.

| 다른 센터·없는 대상 모두 403 | 대상의 존재 여부를 응답으로 알려 주지 않기 위해(ID 추측 방지) | 404/403 구분 |
| 거부 사유는 감사 로그에만 | 응답은 "권한 없음" 하나로, 사유(시작 전·종료 후·회수)는 담당자 화면에서 감사 로그로 확인 | 응답에 사유 표시 |
| CSRF 토큰 대신 Origin 검사 | SPA와 API가 같은 출처이고 SameSite=Strict 쿠키를 쓰므로 Origin 허용 목록만으로 충분하고, 토큰 저장소(XSS 노출면)가 생기지 않음 | 이중 제출 쿠키 |
| 정정은 새 행 | 기록을 덮어쓰지 않아야 누가 언제 무엇을 바꿨는지 남는다 | UPDATE로 수정 |
| 보관 기간 확정(2026-10-13) | 아동 정보·기록·메모는 이용을 마치면 지체 없이 파기(개인정보 보호법 제21조, 제22조의2). 감사 로그·연결 끊긴 배정·비활성 계정은 3년(안전성 확보조치 기준 제5조 ③ 권한 내역 3년, 제8조 접속기록 — 민감정보 처리 시스템 2년 이상). 만료 세션·사용 초대는 30일 뒤 `ieogagi-cleanup`(소유자 역할)으로 삭제. 서버 로그는 10MB×5개 회전. 운영 절차는 `deploy/README.md` 2-1절 | 기한 없이 보관(행이 계속 쌓임), 이용 종료 후 ○년 일괄 보관 |
| 아동 파기 때 배정은 연결만 끊음(2026-10-12 확정) | 배정 행에는 멘토·기간만 남고 아동 연결은 끊겨 아동 개인정보가 남지 않음. 지우면 "배정이 끝난 활성 계정" 신호가 사라져 계정 정리를 놓친다(기획서는 배정 행 삭제였음) | 배정 행 삭제 |
| 민감어 확인은 서버에서 | 프론트를 우회해도 같은 확인을 받게. 단 수학 용어(약수·약분·진단평가)는 오탐하지 않게 단어 선택 | 프론트에서만 확인 |
| 메모 원문은 민감정보 처리 근거를 확인한 아동에만, 암호화해 저장 | 건강·가정 사정은 민감정보가 될 수 있어 별도 동의나 법령상 근거가 있을 때만 처리하고, 처리할 때는 유출·변조되지 않게 안전성 확보 조치를 해야 한다(개인정보 보호법 제23조 민감정보의 처리 제한). 그래서 아동 등록 때 민감정보 처리 근거를 따로 확인한 아동에만 담당자 메모 원문을 쓸 수 있고(F2), 원문은 AES-256-GCM으로 암호화해 담당자만 본다(S15) | 모든 아동에 메모 허용, 평문 저장 |
| 초대 코드·세션 토큰은 HMAC 저장 | 평문 저장 시 DB 유출 = 계정 탈취. 고엔트로피 토큰이라 argon2 같은 느린 해시는 불필요 | 평문, 솔트 없는 SHA-256 |

- 설계: 기획서의 인가 규칙을 Claude Code(Anthropic)와 함께 코드 구조로 옮김. 사람이 정한 원칙(배정 기간 = 권한)을 공통 함수·의존성 타입·Semgrep 규칙 3중으로 고정.
