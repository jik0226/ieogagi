## 1. 04.02 오류 상황 대응 부재

- **원인**: 3차 외부 점검(10/17) 2번 조치로 '코드 숨기기' 때 클립보드의 초대 코드를 지우게 하면서, 브라우저가 거부하면 "넘어감"으로 정하고 catch에 주석만 남겼다. 우리 점검이 놓친 이유는 두 가지다. ESLint `no-empty`는 주석이 든 블록을 빈 블록으로 보지 않고, 자체 빈 예외 규칙(`ieogagi-no-empty-except`)은 Python만 본다.
- **조치**
  1. `utils/clipboard.js`의 `clearClipboard()`가 성공·실패를 돌려준다. 실패하면 InviteForm이 "클립보드에서 초대 코드를 지우지 못했습니다. 다른 글자를 한 번 복사해 덮어 써 주세요"를 경고(`role=alert`)로 보여 준다. 예외 이름·메시지는 화면에 싣지 않는다(시스템 정보 노출 방지).
  2. 같은 패턴 전수 점검: `AuditTab`의 `listUsers().catch(() => [])`가 계정 목록 실패를 삼키고 있었다. 지금은 "이름 대신 번호로 보여 줍니다" 안내와 다시 불러오기 버튼을 보여 준다. Python `except: pass`·`...`·`continue`와 `contextlib.suppress`는 원래 0건이었고(규칙 테스트 픽스처는 제외), JS 빈 catch는 조치 뒤 0건이다.
  3. 재발 방지: Semgrep `ieogagi-fe-empty-catch`(빈 catch와 빈 `.catch` 처리기, `finally`가 붙은 형태 포함)와 ESLint `no-restricted-syntax`(`CatchClause[body.body.length=0]`)를 추가했다. 두 규칙 모두 옛 InviteForm을 검출한다. ESLint는 진단과 같은 32행을 가리킨다.
- **진단 쪽 권고(오류를 로그 파일에 기록)에 대한 판단**: 브라우저에는 로그 파일이 없다. console 출력은 사용자 누구나 볼 수 있어서 자체 규칙('제거되지 않고 남은 디버그 코드')으로 막아 두었다. 서버로 오류를 모으는 API는 로그 주입·도배라는 새 공격면이 생기므로 만들지 않았다. 대신 이 기능의 목적(공용 PC에 코드를 남기지 않기)에 맞게, 사용자가 직접 할 수 있는 조치를 알려 준다.
- **검증**: `npm --prefix frontend test`(node:test 3개: 성공, 거부, API 없음), Semgrep 규칙 테스트 26/26, ESLint 0, `vite build`.

## 2. 02.10 사용자 하드디스크에 저장되는 쿠키를 통한 정보 노출

- **원인**: HttpOnly·Secure·SameSite=Strict는 이미 있었다. 디스크에 남지 않게 하려고 일부러 Max-Age 없는 세션 쿠키로 설계했는데, 브라우저의 '이전 세션 이어서 열기'가 세션 쿠키를 복원하면 브라우저 쪽 수명에는 상한이 없다. 진단 기준도 짧은 수명(`max_age`)을 명시하라고 권한다.
- **조치**
  - `Max-Age = 서버 유휴 만료`: 기본 600초이고, 설정 상한 60분이라 3,600초를 넘지 않는다. 속성은 `set_session_cookie` 한 곳에서만 정한다.
  - `SessionCookieRefreshMiddleware`: 세션 확인을 통과한 요청에만 같은 토큰으로 Max-Age를 다시 내려준다(슬라이딩). 그래서 브라우저 쿠키와 서버 세션이 같은 시점에 끝난다. 세션이 없거나 만료된 요청에는 쿠키를 내려주지 않아 죽은 세션을 늘리지 않는다. 로그인·로그아웃처럼 스스로 쿠키를 정한 응답은 건드리지 않는다. 서버는 지금처럼 유휴 10분·절대 8시간·폐기를 따로 판정한다.
  - 미들웨어로 만든 이유: 의존성에서 쿠키를 붙이면 Response를 직접 돌려주는 라우트(아동 파기 204)에서 갱신이 빠진다.
  - Secure 개발용 분기는 두지 않았다. 브라우저는 `http://localhost`를 보안 컨텍스트로 보므로 개발이 그대로 되고, `__Host-` 접두사는 Secure가 없으면 쿠키 자체를 거부한다. 분기 스위치는 운영에서 잘못 켜질 위험만 늘린다.
- **검증**: `backend/tests/test_session_cookie.py` 6개. 로그인 응답 속성, 인증 응답 갱신(같은 토큰), Response 직접 반환 라우트 갱신, 세션 없음·만료 시 쿠키 없음, 로그아웃은 삭제 쿠키 1개만, 설정 상한 60분을 확인한다.

## 4. 요점

- **수명은 서버가 정하고 브라우저는 따라간다**: 쿠키에는 의미 없는 토큰만 있고, 만료·폐기·권한은 요청마다 DB에서 판정한다. 이번 조치로 브라우저 쪽 쿠키 수명도 서버 유휴 만료에 맞췄다.
- **오류는 삼키지도, 노출하지도 않는다**: 사용자에게는 할 수 있는 조치를 고정 문구로 알리고, 예외 문구·스택은 화면과 console 어디에도 내지 않는다(서버 쪽은 마스킹한 구조화 로그, 보안설계 S9).
- **놓친 원인을 규칙으로 막는다**: 진단 도구가 잡고 우리 도구는 놓친 형태(주석만 있는 catch)를 자체 규칙과 규칙 테스트로 옮겨, 같은 실수가 커밋 전 단계(pre-commit)에서 걸리게 했다.
