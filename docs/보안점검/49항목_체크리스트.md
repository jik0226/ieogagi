# 이어가기 소프트웨어 개발보안 49항목 점검표

> KISA 「소프트웨어 개발보안 가이드」의 구현단계 보안약점 49개를 이어가기 코드에 하나씩 대조하는 표다. 심사는 정적 분석 도구로 소스를 검사해 **빌드 라인당 보안약점 수**로 점수를 매기므로, 목표는 **0건**이다.
> 도구 실행법은 [점검도구_사용법.md](점검도구_사용법.md), 예외 처리 기록은 [예외_대장.md](예외_대장.md)에 있다.
> 프론트엔드(React/JS)도 진단 대상임을 주최 측에 확인해(10/23) 같이 점검한다. 표의 자동 점검 칸에 `프론트:`로 프론트 규칙을 함께 적었다.

- 담당(2026-10-11 분담 변경): 도구 실행·1차 분류·수정·기록은 **팀장(AI 코딩 도구 활용)**, 진짜 약점인지와 수정 방향의 **최종 판단은 팀장(보안 총책임)**, 사람이 직접 하는 공격 시나리오 테스트는 **보안 테스트 담당**. (원래 문구: 설계·구현 대응은 개발팀이 채우고, 점검 결과 칸은 점검 담당자가 채운다.
- 일정: **10/23 1차 점검**, **10/28 재점검**, 10/30 18:00 제출. 기능 동결도 10/28이다(권장 순서: 오전 재점검 → 필요한 수정 → 오후 동결). 1차 점검에서 나온 수정은 동결 전에 끝낸다.

## 이 표를 채우는 방법

1. `make security`를 돌려 `security/reports/<날짜_시각>/summary.txt`를 만든다. 건수가 0이 아니면 해당 리포트를 열어 어떤 항목(번호)에 해당하는지 찾는다.
2. 항목별로 **자동 점검** 칸의 규칙이 잡은 건이 있는지 보고, **수동 점검 방법** 칸대로 직접 확인한다. 자동 규칙이 없는 항목은 수동 점검이 전부다.
3. 결과를 **1차 결과(10/23)** 칸에 코드로 적는다. 재점검(10/28)에서 바뀐 내용은 같은 칸 뒤에 `→ 재점검 OK`처럼 이어 쓴다.
4. 고칠 것이 있으면 이슈를 만들고, **조치·사유** 칸에 이슈 번호와 커밋(또는 PR)을 적는다. 오탐·수용은 [예외 대장](예외_대장.md)에 번호를 매겨 올리고 이 칸에 `예외 #번호`로 연결한다.
5. 49개 모두 칸이 채워지고 도구 건수가 0(또는 예외 대장에 사유가 있는 건만 남음)이면 점검 완료다.

### 1차 점검 결과 (2026-10-23)

- 자동 점검: `make security` 8단계 모두 OK(건너뜀 0, 오류 0), `make secrets-scan` OK. main `2441930`, 작업 트리 깨끗함, 로컬 맥에서 10/23 09:56 실행.
- 도구별 건수는 모두 0이다. ruff 0 / bandit 0(높음·중간·낮음 0, `#nosec` 0) / 자체 Semgrep 0(규칙 25개 = 파이썬 17·JS 8, 파일 140개) / 공식 팩 백엔드 0(p/python·p/secrets·p/owasp-top-ten, 규칙 191개, 파일 61개) / 공식 팩 프론트 0(p/javascript·p/react·p/secrets, 규칙 104개, 파일 90개) / pip-audit 0(패키지 36개) / npm audit 0(운영 의존성 8개) / ESLint 0 / gitleaks 0(커밋 46개 + 작업 트리). 공식 팩 규칙 수는 실행 날짜마다 달라질 수 있어 제출 직전 값으로 갱신한다.
- 코드 규모: `backend/app` 4,199줄(bandit 기준), `frontend/src` 3,428줄(빈 줄 제외). 클라우드 `make security-quick`도 같은 값.
- 표의 1차 결과 칸 표기: `자동 0` = 그 항목의 자동 점검 칸에 적은 규칙이 0건, `자동 규칙 없음` = 자동 규칙이 없는 항목. **OK·N/A는 수동 점검까지 끝난 뒤 적는다.** 수동 점검 결과는 보안 테스트 담당 결과표(1차 ~10/26, 재점검 10/28)와 수동 대조 뒤 같은 칸에 `→ 수동 OK`처럼 이어 쓴다.
- `DONE`은 1차 점검 전에 외부 점검(10/13·10/15·10/17)이나 사실 대조로 찾아 이미 고친 항목이다. 10/28 재점검에서 다시 확인한다. 조치·사유 칸의 커밋은 [보안설계.md](../보안설계.md) 4-1절 표와 같다.
