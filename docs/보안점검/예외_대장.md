# 보안 점검 예외 대장

> 정적 분석 도구가 잡았지만 고치지 않기로 한 건을 모두 여기에 적는다. 코드의 `# nosec`·`# noqa`·`# nosemgrep` 주석 하나마다 이 표에 같은 번호의 행이 있어야 하고, 이 표의 행마다 코드(또는 도구 설정)에 그 번호가 적혀 있어야 한다. 사용법은 [점검도구_사용법.md](점검도구_사용법.md)의 6절을 본다.

## 작성 규칙

1. **번호**는 1부터 이어서 매긴다(삭제해도 번호를 재사용하지 않는다). 코드 주석에 같은 번호를 쓴다: `# Exception ledger #3 (false positive): <reason in English>`
2. **판단**은 둘 중 하나다.
   - `오탐`: 도구가 잘못 잡았다. 실제로는 그 약점이 생기지 않는다. 사유에 왜 생기지 않는지를 쓴다.
   - `수용`: 약점이 있다는 것은 알지만 위험이 낮거나 대안이 없어서 두기로 했다. 사유에 위험이 낮은 이유와 보완책을 쓴다.
3. **확인자**는 1차 분류한 사람(AI 코딩 도구를 쓴 팀장)과 최종 판단한 팀장을 함께 적는다(팀장 확인 없는 예외는 없다). 한 사람만 확인한 건은 주석을 달지 않고 먼저 리드에게 묻는다.
4. 해결되어 주석을 지웠다면 행을 삭제하지 말고 **사유**에 `해소(날짜, 커밋)`를 덧붙인다.
5. 체크리스트의 **조치·사유** 칸에는 `예외 #번호`로 연결한다.
