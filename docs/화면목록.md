# 이어가기 화면 목록

> 화면 6개의 경로·역할·호출 API·상태 처리·디자인 메모. API 번호는 `docs/API_설계.md`의 `#` 번호다. 화면 코드는 `frontend/`에 있다. 이 표와 앱이 다르면 앱이 기준이고 이 표를 앱에 맞춘다.

## 공통 동작

| 항목 | 동작 | 호출 API |
|---|---|---|
| 앱 시작 | `GET /api/auth/me`로 로그인 여부 확인. 401이면 `/login`, 성공하면 역할별 홈으로 이동 | #5 |
| 역할별 홈 | 멘토 `/mentor`, 시설장·담당자 `/staff` | – |
| 다른 역할의 경로 | 자기 홈으로 보냄 (멘토가 `/staff` → `/mentor`, 담당자가 `/mentor` → `/staff`) | – |
| 로그아웃 | 상단 헤더 버튼. 세션이 이미 끝났어도 로그인 화면으로 이동 | #4 |

| 헬스 체크 | 화면에서는 부르지 않는다. `src/api/health.js`에 함수만 있다 | #27 |

## 민감정보 확인 흐름 (S4)

1. 멘토가 회차 기록을 저장하면 `POST /api/children/{child_id}/records`(#19) 또는 정정(#20)을 `sensitive_confirmed: false`로 보낸다.
2. 서버가 건강·가정 관련 단어를 찾으면 422 `SENSITIVE_CONFIRM_REQUIRED`와 `categories`(`health`, `family` 중 일부)를 돌려준다. 이 오류는 일반 오류 박스로 보여 주지 않는다.
3. 화면은 확인창을 띄운다. 제목은 감지된 분야로 정한다: "건강 관련 내용이 있는 것 같아요" / "가정 관련 내용이 있는 것 같아요" / "건강·가정 관련 내용이 있는 것 같아요". 본문: "기록은 다음 선생님에게도 전해집니다. 학습 내용만 남겼는지 확인해 주세요. 건강·가정 정보는 담당 선생님께 직접 알려 주세요."
   - **수정하기**: 창을 닫고 입력 화면으로 돌아간다. 입력한 내용은 그대로 남는다.
   - **그래도 저장**: 같은 내용을 `sensitive_confirmed: true`로 다시 보낸다. 성공하면 아동 기록 화면으로 이동한다.
4. 담당자는 나중에 S6에서 해당 칸의 내용만 지울 수 있다(#22).
5. 감사 로그 action `record.sensitive_prompt`는 이 확인 요청을 가리킨다(기록은 서버 담당).

## 403 메시지 정책

- 403은 역할 부족, 다른 센터, 배정 기간 밖, 회수된 배정을 가리지 않고 **같은 문구**로 안내한다: "열람 기간이 아니거나 권한이 없습니다." 이유를 구분해서 알려 주면 기간·배정 존재 여부가 새어 나간다.
- 서버가 보내는 `message`와 관계없이 화면은 고정 문구를 쓴다(`src/utils/messages.js`).
- 멘토 화면의 403(조회 중이든 저장 중이든)은 ⛔ 전용 차단 화면으로 보여 준다(`components/ForbiddenView.jsx`): 제목 "열람 기간이 아니거나 권한이 없습니다", 본문 "배정 기간이 끝났거나 회수된 아동의 기록은 볼 수 없습니다. 필요하면 담당 선생님께 문의하세요.", 버튼 "내 아동으로". "다시 시도" 버튼은 붙이지 않는다. 다시 시도해도 결과가 같기 때문이다.
- 담당자·시설장 화면의 403은 노란 경고 박스에 같은 문구를 쓴다.
- 멘토 홈(S2)에서 "시작 전" 배정은 눌러지지 않게 해서 403이 나는 요청을 미리 보내지 않는다. 그래도 주소를 직접 입력해 들어오면 S3·S4가 차단 화면으로 막는다.

## 그 밖의 오류 문구 정책

| 상황 | 화면 처리 |
|---|---|
| 401 `UNAUTHENTICATED` | 로그인 화면으로 이동하고 "세션이 만료되었습니다. 다시 로그인해 주세요." 안내(세션 만료·비활성 계정 포함). 앱을 처음 열 때의 로그인 확인은 안내 없이 로그인 화면 |
| 401 `LOGIN_FAILED` | 서버 문구 그대로 표시. 아이디가 틀렸는지 비밀번호가 틀렸는지 구분하지 않는다 |
| 409, 422 `VALIDATION_FAILED` | 서버 `message` 표시(409 이미 정정된 기록은 "이미 정정된 기록입니다. 최신 기록을 정정해 주세요."). 422는 `fields`에 해당하는 칸에 "입력 값을 다시 확인해 주세요." 표시 |
| 429 | 서버 `message`, 없으면 "요청이 너무 많습니다. 잠시 후 다시 시도해 주세요." |
| 500·네트워크 실패·형식이 다른 응답 | 멘토 화면은 "문제가 생겼습니다 / 잠시 후 다시 시도해 주세요. / 다시 시도" 화면, 그 밖에는 "요청을 처리하지 못했습니다…" 또는 "서버에 연결하지 못했습니다…"만 표시. 응답 본문·스택은 화면에 내지 않는다 |
